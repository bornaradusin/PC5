PC5 2.0.3 brings a web page and FTP login for managing PC5 from a phone or PC, installing games on a USB drive, a Steam emulator, PhysX and other redistributables, smaller games, faster loading, and many fixes from your reports.

### Install

- **ProsperoStore**: update PC5 from its page in the store.
- **PC5's own updater**: **Settings › System › Update now**, or **Update now** when PC5 asks as it opens. It downloads only what changed when you have the version before, otherwise the whole app. PC5 restarts by itself when the update is installed.

**Going back:** a game installed with 2.0.3 needs 2.0.3 or newer: on 2.0.2 it is missing Windows' own files, so install it again there. Games installed before keep working on any version.

### What's new

- **Install on a USB drive** (replaces Play from USB): with a USB drive plugged in, PC5 asks where a game goes, **Console** or **USB drive**. On the drive it goes in its `PC5` folder and plays from there; its saves stay on the console. Uninstalling deletes it from the drive too. Games set to play from a USB drive with an earlier PC5 keep working.
- **An INSTALL folder on each USB drive**: `PC5/INSTALL`. Games put there are offered as those in PC5's own INSTALL folder are, when PC5 opens or when the drive is plugged in. Installed on that same drive, a game is moved at once instead of copied.
- **Settings › Network**: the FTP server moved here from Game maintenance, with an on/off switch, a **Username** and an optional **Password**. With none set, any login works, as before.
- **Web page**: in **Settings › Network**, turn on **Web page** and open the address it shows in a browser on your phone or PC. From there you can send a game's folder to PC5 (it then asks to install it), edit a game's launch options (`launch.txt`, `env.txt`), and download a game's newest log and the kept logs. It asks for the same username and password as the FTP server.
- **Games made for Steam**: a game whose copy needs Steam's `steam_api64.dll` gets an emulator in its place (gbe_fork), so it starts without Steam's client. **△ › Manage › Steam emulator** turns it off for a game. Programs wrapped in Steam's DRM (SteamStub) still don't start; PC5 now says why instead of crashing.
- **PhysX and other redistributables**: the first time a game starts, PC5 installs the packages it carries (`_CommonRedist`, `Redist`, `PhysX` folders, and PhysX inside a setup program), such as NVIDIA's PhysX, once. A PhysX runtime copied into a game's Windows by hand is registered as its setup program would.
- **Smaller games**: each game you install takes about 300 MB less and installs sooner. Wine's DLLs are no longer copied into every game.
- **A smaller PC5**: about 110 MB smaller to download and 300 MB smaller on the console.
- **Faster loading**: small reads come from a bigger piece of the file read ahead, and opening a file costs fewer steps. Games with many small files load faster.
- **The library shows at once**: the check for a newer PC5 runs in the background.

### Fixes from your reports

- **"Too many open files"**: games that keep many files open (an Unreal Engine game's archives, an older game's packages, .NET games with large folders) ran out of the files a console program can open, and stopped or failed to load the next level. Files a game only reads are now closed when unused and opened again when needed.
- **Shaders an older game builds at start**: a game that runs its own shader compiler as a second program, which the console can't start, drew blurry, repeating textures. PC5 now does that compiler's work inside the game.
- **Unreal Engine 5 games that ran extremely slowly** (0 to 1 fps, minutes at "Starting"): the game's frequent memory checks kept Wine's memory lock busy, and the game ran on about one core. They now cost almost nothing.
- **Games that read the network adapter's address**: the console had no adapter to show besides the internal one, and a game that didn't check the answer crashed. PC5 now shows an unplugged wired adapter, as a PC with its cable out has: such games see themselves offline.
- **.NET parts of a native game**: a game that loads a .NET library beside its program now gets the .NET runtime, as a .NET program does.
- **Older games that crashed reading `FFFFFFFF`** at start: the instructions the console refuses (SGDT, SIDT and others a CPU check or anti-tamper runs) now work.
- **Godot games** on OpenGL open their window ("Failed to create an OpenGL window").
- **Source engine games** no longer hang at start.
- **32-bit games** whose memory landed above 4 GB.
- **A controller turned off and on again** is seen again by the game.
- **A game that crashes** now closes instead of freezing.
- **Direct3D 9 effects** that games build from their source, and a Direct3D 9 reset onto a new window.
- **Listing a game's subfolders** in .NET games.
- **A game that lists or replaces one of Windows' DLLs** sees Wine's there, and gets its own copy before it changes one.

### Which games run

See the [game compatibility list](https://github.com/bornaradusin/PC5/wiki/Game-compatibility), made from players' reports and issues. Got a game running? [Add it](https://github.com/bornaradusin/PC5/discussions/new?category=game-compatibility): the form takes a minute.

### Reporting a problem

Please report problems as an [issue on GitHub](https://github.com/bornaradusin/PC5/issues/new/choose), not in ProsperoStore's comments:
- **A game doesn't run** for a game.
- **A problem with PC5** for PC5 itself.

Attach the game's zip from `/data/prospero-win/logs/`: an `issue-…zip`, or the game's newest `log-…zip` when nothing crashed. The form asks for it, as the cause can't be found without it. **△** on PC5's crash message opens the form for you, filled in.

If an update from PC5 fails, the message says why. Turn on **Settings › System › Keep all logs**, try again and attach PC5's own log. See [Logs and debugging](https://github.com/bornaradusin/PC5/wiki/Logs-and-debugging) for what an issue may ask for.

### Not supported

- Games that need a store's launcher or client running (Steam, EA app, Ubisoft Connect, Rockstar Games Launcher).
- Anti-cheat, games that need kernel drivers, and DRM-protected games.
- .NET programs that mix .NET and C++ (C++/CLI).
- 16-bit Windows and DOS programs.
- Recording or saving video from inside a game.
- Frame generation for DirectDraw games and games drawn without 3D, and HDR output.
- Changing a game's controller mode, resolution or aspect ratio while it runs.
- Updating a PC5 installed as a package (`.pkg`): it updates from a folder only.
